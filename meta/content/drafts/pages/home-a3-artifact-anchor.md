### Candidate A — RECOMMENDED · a retry-with-backoff integration wrapper (TypeScript)

What this encodes: the pouk.ai thesis made literal. The hard part isn't calling the model, it's the *seam* where the model meets the systems it has to live in. This fragment is the shape of code that keeps a real integration running after the demo: a bounded retry around a flaky upstream, with the decision (retry transient, surface the rest) right there in the code.

- **`language`**: `typescript`
- **`code`** (verbatim — longest line 44 chars):
```ts
// keep it running after the demo:
// retry the transient, surface the rest
async function call(input: Input) {
  for (let attempt = 1; ; attempt++) {
    try {
      return await upstream(input)
    } catch (err) {
      if (!isTransient(err) || attempt === 3) throw err
      await sleep(250 * 2 ** attempt)
    }
  }
}
```
- **`caption`** (mono register): `integration.ts — keeping it running, not just standing it up`
- **`label`** (accessible name for the `<pre>`): `Example fragment: a retry wrapper around a flaky upstream integration`

**Why recommended.** It is the single fragment that most directly says *how pouk.ai thinks*: it is about the seam, not the model. It pays off the Statement ("keep it running"), the MIT NANDA cause ("the gap is integration"), the `builds` discipline ("wired into the tools you already run on"), and the comparison's pouk.ai axis ("the integration is the hard part and it has to keep running after the demo") all at once. The two comment lines do the framing so the caption can stay terse. It is short, narrow (44 chars max), reads at a glance, and contains zero fabricated metrics, zero chrome, zero client-identifying material. **Real-decision it must encode (Arian to confirm):** that pouk.ai genuinely writes bounded-retry integration wrappers of roughly this shape (retry only transient failures, cap attempts, exponential backoff) and stands behind this as representative of its integration work. If the real wrapper differs (different cap, jitter, a circuit breaker), swap in the true version.

### Candidate B — an automation's core: a scheduled triage step (Python)

What this encodes: the `automations` discipline made literal. The unit of an automation is "the manual, repeated work between your systems, running without a person in the loop." - **`language`**: `python`

- **`caption`** (mono register): `triage.py — the loop a person used to run by hand`

**Why strong.** It reads at a glance even to a non-Python reader, and it makes the `automations` discipline concrete (escalate vs. resolve is the real decision an automation encodes). **Trade-off vs. A:** it maps to one discipline (automations) rather than to the whole page's thesis; A maps to the Statement + the figure + the comparison together. **Real-decision it must encode (Arian to confirm):** that pouk.ai builds triage/routing automations of this shape and that `needs_human` / `escalate` / `resolve` is a fair abstraction of real work, not a toy.
